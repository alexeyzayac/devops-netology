### Решение:

5. Суть исправленных синтаксических ошибок:
* **Опечатка в platform_id (файл main.tf, строка 15). Было написано "standart-v4"** — правильно "standard-v4". Однако платформы standard-v4 в Yandex Cloud не существует, поэтому выбрана standard-v1, которая поддерживает core_fraction = 5 [Документация](https://yandex.cloud/ru/docs/compute/concepts/vm-platforms).
* **Недостаточное количество vCPU для standard-v1 с core_fraction = 5.** Для платформы standard-v1 при core_fraction = 5 минимальное количество ядер — 2. В исходном коде было cores = 1, что вызывало ошибку. Исправлено на cores = 2.
* **Неправильная передача SSH-ключа в метаданные (файл main.tf, строка 38).** В переменной vms_ssh_public_root_key хранился путь к файлу ключа, а не его содержимое. В результате в metadata попадала строка "../secrets/my_ed25519_key.pub" вместо реального публичного ключа. Исправлено на: `ssh-keys = "ubuntu:${file(var.vms_ssh_public_root_key)}"`. Теперь функция file() читает содержимое файла и передаёт корректный ключ.

8. Роль параметров preemptible = true и core_fraction = 5 в обучении:
* **preemptible = true** — создаёт прерываемую ВМ. Yandex Cloud может остановить её в любой момент (но не чаще раза в 24 часа). Стоимость такой ВМ в несколько раз ниже обычной. В обучении это идеально для тестовых стендов, временных окружений, CI/CD-агентов и любых задач, где не требуется 100% отказоустойчивость. Позволяет существенно экономить бюджет.

* **core_fraction = 5** — гарантирует, что ВМ получит 5% производительности физического ядра процессора. При простое хоста может временно использовать до 100%. Значение 5% достаточно для нетребовательных задач (веб-серверы в режиме разработки, лёгкие скрипты, системы мониторинга). В сочетании с preemptible = true даёт максимальную экономию на учебных проектах.
