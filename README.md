### Задание. Необходимо определить требуемые ресурсы
Известно, что проекту нужны база данных, система кеширования, а само приложение состоит из бекенда и фронтенда. Опишите, какие ресурсы нужны, если известно:

1. Необходимо упаковать приложение в чарт для деплоя в разные окружения. 
2. База данных должна быть отказоустойчивой. Потребляет 4 ГБ ОЗУ в работе, 1 ядро. 3 копии. 
3. Кеш должен быть отказоустойчивый. Потребляет 4 ГБ ОЗУ в работе, 1 ядро. 3 копии. 
4. Фронтенд обрабатывает внешние запросы быстро, отдавая статику. Потребляет не более 50 МБ ОЗУ на каждый экземпляр, 0.2 ядра. 5 копий. 
5. Бекенд потребляет 600 МБ ОЗУ и по 1 ядру на копию. 10 копий.

### Решение:

#### Требования приложений:

| Приложение  | Кол-во реплик | RAM (1 ед.) | CPU (1 ед.) | Итог RAM | Итог CPU | 
|-------------|---------------|-------------|-------------|----------|----------|
| База данных | 3 пода        | 4 GB.       | 1 core      | 12 GB.   | 3 core   |
| Кеш         | 3 пода        | 4 GB.       | 1 core      | 12 GB.   | 3 core   |
| Фронтенд    | 5 подов       | 0.05 GB.    | 0.2 core    | 0.25 GB. | 1 core   |
| Бекенд      | 10 подов      | 0.6 GB.     | 1 core      | 6 GB.    | 10 core  |
| Всего       | 21 под        |             |             | 30.25 GB.| 17 core  |

#### Запас на отказоустойчивость:

Чтобы кластер оставался работоспособным при потере одной рабочей ноды, необходимо, чтобы оставшиеся ноды могли обеспечить все требуемые ресурсы.

**Выбранная конфигурация 1 узла:**
* CPU: 8 ядер
* RAM: 16 ГБ

**Расчёт доступных ресурсов на один узел с учётом служебных нужд:**

| Ресурс  | На 1 узел | Резерв системы | Доступно для подов |
|---------|-----------|----------------|--------------------|
| CPU     | 8 core    | 0.6 core       | 7.4 core           |
| RAM     | 16 GB.    | 4.2 GB.        | 11.8 GB.           |

*Обоснование резервирования:*
* ОС и kubelet: CPU ~ 0.09 ядра, RAM ~ 2.7 GB.
* Запас на DaemonSet: CPU ~ 0.5 ядра, RAM ~ 1.5 GB.
* Итог: CPU ~0.6 ядра, RAM ~4.2 GB.

*При 3 узлах после отказа одного останется 2 узла:*
* Доступный CPU: 2 x 7.4 = 14.8 ядра (не хватает 2.2 ядра)
* Доступная RAM: 2 x 11.8 = 23.6 GB. (не хватает 6.65 GB.)
* **Итог: нужно минимум 4**

*При 4 узлах и потере одного останется 3 узла:*
* Доступный CPU: 3 x 7.4 = 22.2 ядра (требуется 17 ядер)
* Доступная RAM: 3 x 11.8 = 35.4 GB. (требуется 30.25 GB.)
* **Итог: обеспечивают запас**

#### Итоговая конфигурация кластера

| Параметр                       | Значение                                                            |
|--------------------------------|---------------------------------------------------------------------|
| Количество рабочих узлов       | 4 ноды                                                              |
| Размер одного узла             | 8 CPU, 16 GB. RAM                                                   |
| Всего CPU / RAM в кластере     | 32 ядра / 64 GB.                                                    |
| Зарезервировано на узел        | ~0.6 CPU, ~4.2 GB. RAM                                              |
| Доступно подам (на узел)       | ~7.4 CPU, ~11.8 GB. RAM                                             |
| Доступно подам (всего)         | ~29.6 CPU, ~47.2 GB. RAM                                            |
| Использование CPU / RAM        | 17 / 29.6 (≈57%) / 30.25 / 47.2 (≈64%)                              |
| Отказоустойчивость             | При поторе 1 узла (остаётся 3 узла: 22.2 CPU, 35.4 GB. RAM)         |
| Запас после отказа (CPU / RAM) | +5.2 ядра (~30%) / +5.15 GB. (~17%)                                 |
