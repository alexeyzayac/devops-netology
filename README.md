## Задача 2

Выберите один из вариантов платформы в зависимости от задачи. Здесь нет однозначно верного ответа так как все зависит от конкретных условий: финансирование, компетенции специалистов, удобство использования, надежность, требования ИБ и законодательства, фазы луны.

Тип платформы:

- физические сервера;
- паравиртуализация;
- виртуализация уровня ОС;

Задачи:

- высоконагруженная база данных MySql, критичная к отказу;
- различные web-приложения;
- Windows-системы для использования бухгалтерским отделом;
- системы, выполняющие высокопроизводительные расчёты на GPU.

Объясните критерии выбора платформы в каждом случае.

## Решение

* Для высоконагруженной MySQL, критичной к отказу, лучше выбрать физические серверы или паравиртуализацию с прямым доступом к оборудованию, чтобы обеспечить предсказуемую производительность I/O и избежать влияния соседей.
* Web-приложения оптимально размещать на виртуализации уровня ОС (контейнерах) благодаря быстрому развёртыванию, масштабированию и высокой плотности размещения.
* Windows‑системы для бухгалтерии стоит строить на паравиртуализации (VMware, Hyper-V) — это даёт полную изоляцию, простоту администрирования и соответствие требованиям ИБ и лицензирования.
* Для высокопроизводительных расчётов на GPU предпочтительны физические серверы или паравиртуализация с пробросом GPU, чтобы обеспечить максимальную производительность и прямой доступ к ускорителям.

## Задача 3

Выберите подходящую систему управления виртуализацией для предложенного сценария. Опишите ваш выбор.

Сценарии:

1. 100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий.
2. Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин.
3. Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры.
4. Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux.

## Решение

* 100 ВМ (Linux/Windows) с балансировкой, репликацией и резервным копированием
Proxmox VE – бесплатное open-source решение на базе KVM и LXC. Включает встроенные инструменты резервного копирования, репликацию, поддержку кластеризации и API для интеграции балансировщиков нагрузки, идеально подходит для смешанных сред.

* 20–30 серверов, требуется максимальная производительность (open-source)
Proxmox VE – сочетает производительность KVM с удобным веб-интерфейсом, управлением кластером и минимальными накладными расходами, что делает его оптимальным для небольшой инфраструктуры с ВМ под Linux и Windows.

* Бесплатное, максимально совместимое и производительное решение для Windows-инфраструктуры
Microsoft Hyper-V Server – нативный гипервизор от Microsoft, обеспечивает наилучшую совместимость и производительность для Windows-гостей, распространяется бесплатно (без графической оболочки).

* Тестирование ПО на нескольких дистрибутивах Linux
Oracle VirtualBox – бесплатный гипервизор 2-го типа, простой в настройке, поддерживает множество гостевых ОС, идеально подходит для изолированных тестовых окружений на рабочей станции.

## Задача 4

Опишите возможные проблемы и недостатки гетерогенной среды виртуализации (использования нескольких систем управления виртуализацией одновременно) и что необходимо сделать для минимизации этих рисков и проблем. Если бы у вас был выбор, создавали бы вы гетерогенную среду или нет?

## Решение

### Проблемы:

* Сложность управления (разные интерфейсы, терминология, компетенции).
* Нет единой отказоустойчивости (HA/DRS) и распределения ресурсов.
* Усложнение сети, хранения, безопасности.
* Рост стоимости (двойное лицензирование, накладные расходы).

### Что делать:

* Внедрить единую плоскость управления (Terraform, Azure Arc, VMware Aria).
* Унифицировать хранение (внешняя СХД) и сеть (стандартные протоколы).
* Централизовать мониторинг и логи.
* Чётко разделить зоны ответственности и автоматизировать сборку образов.

### Выбор:
Создавать гетерогенную среду осознанно не рекомендую, если только это не временный этап миграции или жёсткое требование специфических нагрузок. Для большинства задач один стек (VMware, Hyper-V или KVM) значительно дешевле в поддержке и надёжнее.
