# Домашнее задание к занятию 4 "`Микросервисы: масштабирование`" - `Заяц Алексей`

Вы работаете в крупной компании, которая строит систему на основе микросервисной архитектуры.
Вам как DevOps-специалисту необходимо выдвинуть предложение по организации инфраструктуры для разработки и эксплуатации.

## Задача 1: Кластеризация

Предложите решение для обеспечения развёртывания, запуска и управления приложениями.
Решение может состоять из одного или нескольких программных продуктов и должно описывать способы и принципы их взаимодействия.

Решение должно соответствовать следующим требованиям:
- поддержка контейнеров;
- обеспечивать обнаружение сервисов и маршрутизацию запросов;
- обеспечивать возможность горизонтального масштабирования;
- обеспечивать возможность автоматического масштабирования;
- обеспечивать явное разделение ресурсов, доступных извне и внутри системы;
- обеспечивать возможность конфигурировать приложения с помощью переменных среды, в том числе с возможностью безопасного хранения чувствительных данных таких как пароли, ключи доступа, ключи шифрования и т. п.

Обоснуйте свой выбор.

### Решение:

**Использовать Kubernetes как основную платформу для оркестрации контейнеров и управления микросервисной архитектурой.**

Соответствие требованиям:
* Kubernetes изначально спроектирован для управления контейнеризованными приложениями и поддерживает все популярные runtime (containerd, CRI-O, Docker). Это позволяет запускать сервисы в изолированных средах с гарантированным воспроизведением поведения.
* Встроенный DNS-сервер автоматически регистрирует каждый сервис по его имени, обеспечивая надёжное обнаружение между микросервисами внутри кластера. Для внешней маршрутизации используется объект Ingress в связке с контроллерами, что позволяет гибко направлять запросы к нужным сервисам по хостам, путям и другим правилам.
* Управление количеством реплик реализовано через декларативные объекты. Изменить количество экземпляров можно в любой момент командой kubectl scale или через редактирование манифеста, что позволяет мгновенно увеличивать мощность сервиса при росте нагрузки
* HPA автоматически изменяет количество реплик на основе наблюдаемых метрик или кастомных метрик, поступающих из систем мониторинга. Это позволяет системе адаптироваться к пиковым нагрузкам без ручного вмешательства.
* Тип сервиса ClusterIP делает ресурс доступным исключительно внутри кластера, что идеально для внутренних взаимодействий. Типы NodePort, LoadBalancer и объект Ingress открывают доступ к сервисам извне, при этом чётко контролируется, какие именно эндпоинты и с какими правилами публикуются. Это позволяет строго разграничить внутреннюю и внешнюю сетевые зоны.
* ConfigMap используется для хранения обычных конфигурационных переменных, которые затем передаются в контейнеры как переменные среды или монтируются как файлы. Secret предназначен для чувствительных данных: паролей, токенов, ключей шифрования и сертификатов. Данные в Secret хранятся в закодированном виде, а в etcd кластера могут быть зашифрованы дополнительно. Доступ к Secret можно строго ограничивать с помощью ролевой модели доступа.

**Почему именно Kubernetes:**

1. Kubernetes предоставляет все перечисленные возможности в рамках одной платформы. Нет необходимости собирать сложную связку из нескольких разнородных инструментов — это снижает операционные риски и упрощает поддержку.
2. Kubernetes является стандартом для оркестрации в крупных компаниях. Огромное сообщество, богатая экосистема (Helm-чарты, операторы, инструменты мониторинга и логирования) и совместимость с большинством облачных провайдеров делают его инвестиционно привлекательным выбором на годы вперёд.
3. Платформа позволяет управлять как небольшим проектом, так и тысячами узлов, обеспечивая высокую доступность и отказоустойчивость за счёт встроенных механизмов самовосстановления (перезапуск упавших подов, репликация, обновления без простоя).
